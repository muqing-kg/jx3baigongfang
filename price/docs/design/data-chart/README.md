# 数据图内容规范

> 这套规范回答一个问题：**当一张图要独立被看见、被截图、被转发时，它应该长什么样、怎么用。**
> 它不绑定某个行业，也不依赖某种做法；所有需要“用数据讲清一件事”的内容都可以套用：图表页、数据卡片、文章配图、社媒长图、报告插图。

## 一句话

> **一张图只回答一个问题。标题把问题说清楚，画面把答案放大，颜色只用来区分对象和表达强弱，其余全部让路。**

## 先看结论：8 条

1. **一图一页**：一屏只放一张主图，标题就是它要回答的问题，不设第二个焦点。
2. **不要外框**：图表外面不加框、不加圆角、不加阴影；画面本身就是边界。
3. **标题要大，图内字要小**：标题一眼抓住人，图内文字退到背景里，让数据站出来。
4. **颜色只做两件事**：区分对象（谁是谁）、表达强弱（高/低、快/慢）。不做装饰。
5. **数字要常驻**：颜色只能表达“相对”，精确值必须能读到；色块矩阵每个格子都写数字。
6. **留白要固定**：标题、图、页脚之间的间距全站一致，形成节奏，而不是每页随手调。
7. **互动只做三件事**：移上去看细节、点一下做对比、随时能退出。不要用互动来“解锁”基本信息。
8. **明暗两套，对象色不变**：白天纸白、夜晚深蓝；但对象/分组的颜色在两种模式下完全一样。

## 三张图各回答什么

| 图 | 回答的问题 | 怎么读 | 最容易误读的地方 |
| --- | --- | --- | --- |
| 色块矩阵（前 15 名） | 哪个对象在单点上最强？ | 行是对象，列是第 1–15 名；颜色越深越强，格子里有数字 | 颜色只表达相对强弱，不能拿深浅当精确差值 |
| 分布点图 | 哪个对象稳定？有没有异常记录？ | 每个点是一条记录；同一列是同一个对象；看整列的上下宽度 | 点重叠时不能数“有几条”，只能看分布形状 |
| 区间图 | 哪个对象的典型水平最好？ | 箱子是“中间一半”的范围，横线是正中间，须是常见波动范围 | 箱子短不等于每个值都好，可能是记录少或波动小 |

> 三张图的排序可以不同，这是有意的：色块矩阵按最好成绩排序，区间图按中间水平排序，分布点图按固定名单排序。**排序要让人看得出来，不要偷偷变。**

## 规范用语

整套规范只用左列的词；右列是它在不同内容里的常见说法。写文案时保持同一页内用词一致。

| 规范用语 | 含义 | 换成你的内容可能是 |
| --- | --- | --- |
| 对象 | 被比较的最小单位 | 商品、门店、账号、候选人、设备、供应商 |
| 分组 | 对象的归属集合 | 品牌、部门、地区、渠道、产品线 |
| 指标 | 被比较的数值 | 价格、销量、转化率、耗时、得分、速度 |
| 记录 | 一次可比较的观测 | 一笔订单、一次访问、一天、一次采样 |
| 批次 / 场次 | 一组记录的边界 | 大促、版本、季度、活动 |
| 名次 | 指标从好到差的排序 | 第 1 名、Top 15、排名 |
| 异常记录 | 偏离常态的记录 | 退款、缺货、故障、超时、异常事件 |

**判断能不能套用**：只要你的内容满足“多个对象 × 一个可比较的指标 × 一个明确问题”，这套画面规则就成立。

## 内容语气

图好，字也要跟得上。同一张图里的文字只做三件事：说清问题、给出结论、交代口径。

| 位置 | 怎么写 | 例子 |
| --- | --- | --- |
| 标题 | 一句话问题，或一句话结论 | “哪个对象的单点表现最好？” |
| 图注 | 口径 + 来源，不重复标题 | “2025 年第 3 批 · 单位：分” |
| 浮窗 | 谁 + 多少 + 和谁比 | “对象 A · 86 分 · 比同组高 4 分” |
| 页脚 | 品牌 + 出处 | “数据看板 · example.com” |

五条写法：

1. **先给结论，再给过程**：标题和第一眼画面先回答，细节放到浮窗或图注。
2. **数字先行**：能用数字说清的，不用“大幅”“显著”这类形容词。
3. **少用形容词**：不写“震撼”“炸裂”“史上最强”，让数据自己说话。
4. **术语一致**：同一页里“指标”就一直是“指标”，不要一会儿“数值”、一会儿“得分”。
5. **不解释显而易见的事**：不要在图上写“横轴是对象、纵轴是数值”，读者看得懂；把空间留给口径和异常。

## 怎么用

### 写内容前

先用一句话写出这张图要回答的问题：

- ✅ “哪个对象的单点表现最好？”
- ✅ “哪个对象的典型水平最好，谁最不稳？”
- ❌ “展示一下这批数据。”（这不是问题，读者不知道要看什么）

写不出这句话，就先不要做图。

### 做图时

1. **先定标题和对象顺序**：标题一句话；对象按什么排，先想清楚。
2. **再定颜色**：对象色只区分身份；强弱色只表达大小；品牌色只做签名。
3. **最后加互动**：先保证默认画面能回答标题；互动只负责“看细节”和“做对比”。

### 检查时

- **10 秒测试**：一个没看过数据的人，10 秒内能否说出标题问题的答案？
- **3 击测试**：从打开到看到某个具体数值，最多点 3 次？
- **手机测试**：在手机上，不用放大、不用横屏，能否读完标题和主要结论？
- **截图测试**：只截这一张图发出去，别人能否知道它来自哪里、在说什么？

## 参考图的边界

- `assets/reference/` 里的图片来自一套公开数据看板，**只用于核对版式**：画面比例、留白、字号、颜色关系。
- 图中的品牌、对象代码、指标名称、数值都属于原案例，**本规范正文不使用这些词**；正文统一用“对象、分组、指标、记录”等通用说法。
- 标注“建议”的内容（例如夜晚色块矩阵、列头、跨图对比），是整理时补的，不代表原案例已经这样做。
- 参考图只有静态画面，**没有鼠标移上、点击、手机操作的样子**；`02` 号文档把“能确定的”和“建议的”分开写，落地前需要用真机核对。
- 本规范正文不出现技术做法；需要精确数值时查 [03-制作参数.md](./03-制作参数.md)。

## 使用前检查

- [ ] 一张图只回答一个问题，标题能独立成立。
- [ ] 画面里没有外框、圆角、阴影。
- [ ] 标题最大，图内文字更小；数字对齐、单位只出现一次。
- [ ] 颜色只用于区分对象和表达强弱，没有装饰色。
- [ ] 精确值能读到，不只靠颜色。
- [ ] 标题、图、页脚的间距与其他图一致。
- [ ] 鼠标移上、点击、退出都有明确结果；不遮挡数据。
- [ ] 白天/夜晚两种模式都读得清，对象颜色不变。
- [ ] 手机上不需要放大就能读完标题和主要结论。
